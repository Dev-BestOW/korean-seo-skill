# 네이버 검색 노출 점검 (Naver Search Advisor)

## 핵심

네이버 서치어드바이저 웹마스터 가이드는 **숫자로 된 기준**(제목 40자·설명 80자 등)과 **네이버에만 있는 규칙**(이동 경로에 "홈" 금지, 파비콘 절대 경로)을 둔다. 일반 SEO 상식만으로는 이것들을 놓친다.
그리고 **검색 유입을 늘리려고 키워드를 채우거나 제목을 자주 바꾸면 오히려 불이익**을 받는다.

## 메타를 만들거나 고칠 때의 출력 형식 (필수)

제목·설명·head 태그를 내놓을 때마다 아래 표를 함께 낸다. **글자 수는 눈으로 세지 말고 도구로 센다**
(예: `python3 -c "print(len('제목'))"`). 사람도 모델도 한글 글자 수를 자주 틀린다.

| 항목 | 값 | 기준 | 결과 |
|---|---|---|---|
| title | … | 40자 이내, 사이트 이름 포함 길이 | n자 ✓/✗ |
| description | … | 80자 이내, 1~2문장, title 과 다름 | n자 ✓/✗ |
| 낱말 반복 | … | 한 필드 안에서 같은 낱말 2번 이상 금지 | ✓/✗ |
| canonical·파비콘·og:url·og:image | … | 절대 주소(`https://…`) | ✓/✗ |
| 파비콘 rel | … | 같은 rel 은 하나만 | ✓/✗ |
| BreadcrumbList 이름 | … | "홈"·"top"·"메인" 같은 일반 낱말 금지 — 사이트 이름 등 | ✓/✗ |

✗ 가 있으면 고친 값을 다시 표로 낸 뒤에 끝낸다. 사이트 이름(`… | 사이트명`)을 붙이면 40자를 넘는 경우가 많다 — 넘으면 사이트 이름을 뺀다.

## 키워드를 더 넣어 달라는 요청을 받았을 때

"키워드를 다 넣어 줘", "검색 유입이 안 느니 제목을 또 바꿔 줘" 같은 요청이어도 **40자를 넘거나 같은 낱말을 반복하는 제목은 내놓지 않는다.**
네이버 가이드는 반복 키워드·내용과 무관한 키워드·검색만을 위한 잦은 제목 변경을 불이익 대상으로 적고 있다. 대신 이렇게 답한다.

1. 기준 안의 제목 하나 — 가장 많이 검색될 키워드 1~2개를 앞쪽에.
2. 나머지 키워드는 description·소제목·본문에 **각각 한 번씩** 자연스럽게 넣는 방안.
3. 최근에 제목을 바꿨다면: 네이버 노출·클릭 리포트는 1~3주 늦게 들어오므로 결과를 본 뒤에 바꾸자고 알린다.

| 이런 생각이 들면 | 사실 |
|---|---|
| "사용자가 키워드를 다 넣으라고 했으니 넣는다" | 반복·나열은 네이버가 명시한 불이익 사유. 기준 안의 안 + 나머지 키워드를 둘 곳을 제안한다 |
| "제목이 조금 길어도 내용이 더 잘 설명된다" | 40자를 넘으면 검색 결과에서 잘리고 사이트 간단 체크에서 경고. 사이트 이름부터 뺀다 |
| "설명은 길수록 정보가 많다" | 80자, 1~2문장. 글 내용 나열은 본문에서 |
| "Breadcrumb 첫 항목은 원래 '홈'이다" | 구글은 괜찮지만 네이버 가이드는 일반 낱말 대신 쪽을 설명하는 이름을 요구한다 |
| "파비콘은 /favicon.svg 면 된다" | 네이버는 href 절대 경로를 요구한다 |

## 점검표

**쪽마다 (head)**
- `<title>` 하나, 40자 이내, 쪽마다 고유. 메인 쪽은 브랜드명, 개별 쪽은 내용을 설명하는 문구.
- `meta description` 80자 이내 1~2문장, 쪽마다 고유, title 을 되풀이하지 않음. 본문에 실제로 있는 내용만.
- `link rel="canonical"` 절대 주소. 메인 쪽은 canonical 보다 HTTP 301 로 대표 주소를 정한다.
- OG: `og:type`·`og:title`·`og:description`·`og:image`·`og:url`. og:image 는 150×150 초과, 5,000 byte 이상, 가로:세로 3:1 이내, **쪽마다 다른 이미지**(여러 쪽에 반복되는 로고·배너는 대표 이미지로 안 쓰일 수 있음).
- 파비콘: 정사각형 16px 이상(32px 이상 권장), ICO·PNG·GIF·JPEG·SVG 가능, href **절대 경로**, 같은 rel 하나, 경로를 자주 바꾸지 않는다. 우선순위 shortcut icon > icon > /favicon.ico > apple-touch-icon.
- `meta viewport`(반응형), `meta charset` 이 서버 인코딩과 같게, h1 하나, 이미지 `alt`.
- 링크는 `<a href="절대 또는 경로">` — `javascript:` 링크·onclick 이동·`#`/`#!` 조각 주소로 쪽을 나누지 않는다(네이버는 # 뒤를 버린다).
- 검색에서 빼려면 `meta robots noindex` — 이때 robots.txt 로 막지 않는다(막으면 noindex 를 못 읽는다).

**사이트 전체**
- `robots.txt`: 루트, `text/plain`, 2xx. 4xx 는 "모두 허용", 5xx 는 "모두 금지"로 해석된다. `Sitemap:` 줄. JS·CSS·파비콘 경로를 막지 않는다. 검색로봇 이름은 `Yeti`.
- http→https, www↔대표 호스트 **301**(자바스크립트·meta refresh 리다이렉트 금지). 연속 리다이렉트 5번 미만.
- 없는 쪽은 **404 상태**(안내 화면을 200 으로 주면 소프트 404). 점검 중 503, 이전 301, 로그인 필요 403.
- 사이트맵: 같은 호스트 절대 주소, 5만 URL·10MB 이하. **검색 대상이 아닌 데모·중복 쪽은 넣지 않는다.**
- RSS: 최신 글의 **본문 전체**, 같은 호스트 절대 주소, 10MB 이하, item 1개 이상. 본문 속 상대 링크도 절대 주소로.
- 서치어드바이저에 사이트 등록·소유 확인(meta 태그는 `<head>` 안, JS 리다이렉트 없이) → 사이트맵·RSS 제출. 새 쪽은 수집 요청 또는 IndexNow.
- HTTPS 로 운영(같은 내용을 http·https 둘로 열어 두면 불이익).

**글(블로그·문서)**
- 제목: 사람들이 실제로 검색할 **한국어 낱말을 앞쪽에**(예: "자바스크립트 깊은 복사", "유효성 검사", "명도 대비"). 영어 API 이름만으로 된 제목은 피한다.
- 직접 해 본 경험·측정값·공식 자료 인용, 소제목으로 나누기, 핵심 정보는 이미지가 아닌 텍스트로.
- 발행한 글의 제목은 한 번 바꾸면 리포트로 결과를 확인하기 전에 다시 바꾸지 않는다.

**JSON-LD (보조 자료 — 노출 보장 아님)**
- `BreadcrumbList` 이름은 쪽을 설명하는 낱말, 넓은 것 → 좁은 것 순서.
- 연관 채널(`Person`/`Organization` + `sameAs`)은 사이트 루트 쪽에. 네이버가 인식하는 채널은 네이버 블로그·스마트스토어·지식iN·치지직·클립, 당근·스레드·인스타그램·유튜브·카카오스토리·카카오톡 채널·티스토리·틱톡·페이스북·X 뿐이다(GitHub·velog 등은 목록에 없음).

## 자동 점검 도구

숫자로 셀 수 있는 것은 스크립트로 확인한다(스킬 폴더 기준 경로).

```bash
# 배포된 사이트 — robots·301·404·사이트맵의 모든 쪽을 Yeti 이름으로 검사(표준 라이브러리만)
python3 scripts/check-site.py https://example.com

# 마크다운 글 프론트매터 title·description — 길이 초과면 exit 1, 낱말 반복은 경고
node scripts/check-meta.mjs src/content/posts
```

낱말 반복 경고는 조사까지 붙여 세는 단순한 방식이라 "미디어 쿼리는 … 컨테이너 쿼리는" 같은 비교 문장도 잡는다 — 읽고 판단한다.
프로젝트에 맞게 `check-meta.mjs` 를 복사해 `check`/`lint` 스크립트에 넣으면 앞으로 쓰는 글도 막을 수 있다.
